# ProCode architecture

## macOS desktop delivery

The optional personal-use Apple Silicon app wraps the unchanged production web bundle in Electron. `desktop/main.cjs` owns native windows/menus and a stable `procode://app` origin. `desktop/assets.cjs` serves read-only bundled assets with MIME types and opaque-frame CORS, without a listening HTTP server. No preload bridge or Node integration is exposed to the sandboxed renderer. Network requests are blocked in the app session; HTTPS reference links open externally. Grading-frame timer throttling is disabled while existing runner deadlines stay in force.

The desktop workspace lives under `~/Library/Application Support/ProCode`, independently of browser-origin storage. Package scripts stage only the desktop entry points, production assets and license notices, sign the app locally, exercise the packaged executable with temporary profiles, and create a verified DMG. See [desktop packaging](DESKTOP.md) for build and distribution boundaries.

## Scope and ownership

ProCode is the user's own private application. The user explicitly chose local-first with no paid services. Phase 1 provisions no infrastructure, accounts, or credentials. Real Firebase integration and managed sandbox execution are intentionally deferred until multi-user requirements and budget exist.

## Application

Named method contracts are centralized in `src/app/core/method-policy.ts`. The catalog attaches the method, requirements, and a new exercise version. The ordinary executor first grades the original returned output; a separate instrumented execution records comparisons and object access on method probes. `method-grading.ts` delegates to pure sequence, graph and structure validators under `core/method`, which recognize common comparison/traversal patterns and returns verified, different-method, or unverified feedback. Missing evidence, analyzer failure and analysis timeouts withhold completion while retaining output results. Both Run and Finish show method feedback; only Finish can record a pass after both grades succeed. See [method grading](METHOD_GRADING.md). This local evidence check does not prove complexity or provide tamper resistance.

Angular standalone components and signals hold workspace state. CodeMirror owns editing behavior; the parent owns draft persistence. The content model is independent of components. Difficulty filters the catalog; category and algorithm selectors choose among its exercises. Each exercise has separate JavaScript and Python starters and function contracts. There are 24 junior, 9 skilled, and 10 senior exercises. Explicit exercise-area metadata partitions them into 31 Algorithms and 12 Data structures exercises, with shared editor, difficulty, grading, and progress systems. Linked lists, trees, and stack-focused exercises live in Data structures; array/string, sorting, searching, graph-algorithm, and dynamic-programming tasks remain in Algorithms. SVG icons are local; no remote fonts, images, or scripts are used.

## Editor assistance

CodeMirror's `closeBrackets` and `closeBracketsKeymap` provide language-aware pairing, selection wrapping, closer skipping, and paired Backspace deletion. The autocomplete package was already present transitively and is now declared directly; no completion service or network dependency was added. See the [CodeMirror reference](https://codemirror.net/docs/ref/#autocomplete.closeBrackets).

`components/bracket-colors.ts` decorates parser-recognized delimiters by nesting depth, including expressions inside JavaScript template strings and Python f-strings. Comments, string contents, and regex content cannot change nesting. The plugin updates when the document or syntax tree changes and cycles through three existing contrast-checked syntax tokens. `bracketMatching` also outlines the active pair and underlines unmatched brackets. Appearance changes preserve undo history and update colors through CSS variables.

## Appearance

`src/theme-palettes.json` stores complete Light, Dark, and Midnight OLED token sets for all seven palettes. `scripts/generate-themes.mjs` produces `src/themes.css`, validating complete modes and applying deterministic contrast adjustments recorded in `docs/theme-contrast-adjustments.json`. The build and dev-server startup run this generator offline. Each preset supplies surfaces, text, primary actions, selections, editor syntax, feedback, and corner radii. Midnight OLED uses pure black on the main canvas, sidebar, and editor plus independent low-luminance panels, controls, status fills, selections, text, and syntax colors, rather than inheriting Dark colors.

`Appearance` in `src/app/core/appearance.ts` validates and saves mode/palette identifiers independently of the workspace. `public/appearance-init.js` applies those same validated identifiers before CSS paints. CodeMirror uses CSS tokens and a reconfigurable dark-mode facet, preserving document, selection, and undo history when appearance changes. No remote assets or theme packages are loaded at runtime. The ProCode preset retains blue accents; other presets map vendor colors documented in `THEMES.md`. Claude maps the installed desktop app’s CDS tokens and Claude Light/Dark editor palettes. CodeMirror maps function declarations, control keywords, variables, types, strings, numbers, comments, and operators independently. Theme previews receive the same full token set as the workspace.

## Execution boundary

1. Snapshot exercise, language, source, and inputs when Run or Finish starts.
2. Load the locally served executor source.
3. Create a hidden iframe with `sandbox="allow-scripts"` and **without** `allow-same-origin`.
4. Inside that opaque-origin iframe, create a disposable classic Blob Web Worker. This is deliberately a classic worker: module Blob workers failed to start from the opaque origin in the tested Chromium environment. Python uses dynamic module imports inside the classic worker.
5. Run JavaScript with a captured console or Python using pinned Pyodide 314.0.7 (CPython 3.14). Pyodide is copied from the npm package and served locally, not loaded from a CDN.
6. Apply the exercise adapter: ordinary JSON arguments by default, or node objects for linked-list/tree problems. Grade the function’s returned result, serializing returned linked lists to arrays. Return JSON-compatible outputs. The parent evaluates them using semantic comparators, not source text.
7. Explicitly terminate the worker and remove its iframe on completion, failure, cancellation, or timeout.

The iframe CSP blocks arbitrary network access and allows only local interpreter and method-analyzer scripts. Local serving must provide CORS headers because the frame has an opaque origin. Messages are accepted only from the expected iframe and carry a per-run random channel. The user code runs without the application document, localStorage, cookies, host filesystem mounts, or credentials.

Initialization has a 45-second deadline; user execution has a 4-second wall-clock deadline after the interpreter is ready. Refreshing the page tears down the execution frame and its worker. The runner also retains internal cancellation when replacing an attempt. Each attempt starts with a fresh interpreter. Logs are capped at 100 entries / approximately 8,000 characters; output is capped. Control selection and editing are disabled during execution, and an attempt ID prevents stale results from being recorded after cancellation. Run and Finish stay in place and are disabled while busy; there is no Stop control or visible loading indicator.

The last completed output stays visible during a new attempt. The output region exposes its busy state to assistive technology without displaying loading text or a spinner. Completion replaces logs and grades together, without changing the selected output tab or moving keyboard focus. Code edits and exercise/language changes clear old output. Console renders both attempt-wide failures (syntax, initialization, timeout, cancellation) and grouped per-check exceptions. JavaScript diagnostics keep available solution stack frames and compensate for the Function constructor wrapper when reporting editor line numbers. Python includes bounded tracebacks. Diagnostics are rendered as escaped text, and test details retain their per-check error and hint. JavaScript syntax errors may lack a line number when the browser does not supply one.

This browser boundary is meant for the owner's own algorithm practice, not a hostile multi-tenant code execution service. There is no hard per-worker memory quota; excessive allocation may exhaust the browser. Browser implementations and WebAssembly loading behavior differ. Private tests are not secret, and a determined local user can alter both the grader and saved results. Before offering trusted scores or accepting adversarial code, add backend-controlled test execution in managed sandboxes with memory/CPU/network quotas and independent results verification.

## Grading

Run uses 3 public examples. Finish uses those examples plus deterministic edge/generated cases, with 10 to 18 total checks depending on the exercise. Two Sum accepts any distinct valid indices in either order. Minimum Window accepts any valid minimum-length tied window. Three Sum canonicalizes unique value triplets, accepting arbitrary triplet and value order. Course Schedule Order validates a complete topological order rather than matching one reference ordering. Other exercises use strict primitive or recursive array comparison, preserving value types, order, length, and duplicates. Boolean tasks cannot pass with truthy strings or numbers. Slow-but-correct approaches pass within the execution deadline; complexity is teaching feedback, not an inferred claim. Python and JavaScript share the same example and grading contracts. Each check constructs fresh arguments. The `linked-list` adapter creates nodes for each input list and serializes the returned chain, rejecting malformed nodes, cycles, and more than 1,000 returned nodes. `cycle-list` connects the tail to the specified node index but passes only the head to learner code. `tree` converts nested `[value, left, right]` representations into TreeNode objects. Constructors and fields are documented in starters and requirements. Existing advanced tree exercises keep their original nested-array arguments to preserve saved drafts.

All exercises grade returned results across different inputs. Move Zeroes and Remove Duplicates return the complete result array/list; allocating a new array and modifying then returning the input are equally valid. Console output is diagnostic and does not determine correctness. There are no mutation-only or count/prefix output adapters. Node-based tasks accept compatible returned nodes without requiring a particular class or algorithm.

The executor receives inputs, not expected answers. Comparisons occur in the parent, protecting against accidental mutation of expected values by ordinary solutions. This is not a security guarantee against deliberate score tampering.

## Persistence

One versioned localStorage record (`procode.workspace.v1`) contains preferences, the active practice area, separate selected exercise IDs per area and difficulty, drafts, and completion history. The existing `selectedExercises` map now belongs to Algorithms; `selectedStructures` belongs to Data structures. Legacy selections for moved exercises migrate to the new map and reopen in the appropriate section, preserving IDs, versions, drafts, and completions. Older records without selections migrate to the original challenge for each difficulty; stale or wrong-difficulty IDs fall back to a valid challenge. Category filters are session-only and reset on difficulty or practice-area changes. Progress totals derive from catalog size and two supported languages. Draft keys include exercise ID, content version, and language. Move Zeroes and Remove Duplicates version 1 records migrate to version 2: source is preserved verbatim and earned completions are retained and deduplicated. An existing version 2 draft takes precedence, including an empty draft. Older mutation-only solutions may need an explicit return; migration does not rewrite learner code. Records are validated on read; corrupt data yields a visible warning and a usable fresh session. Failed writes show an export option. Reset replaces only the current draft and retains earned completion. Edits clear stale displayed results but retain historical completion. Data does not sync across browsers, machines, or origins. Export provides a manual JSON backup; import is deferred.

## Knowledge quizzes

`core/quiz/` holds 200 original multiple-choice questions, organized across ten topic IDs. Each entry has a stable ID, four choices, a correct-choice index, explanation, and HTTPS reference. The `Quiz` component is loaded with Angular `@defer` when the quiz section is first opened; algorithms retain their editor instance while hidden. Navigation is in-app state, without a router or remote service.

Session creation samples without replacement and shuffles choice indices with Fisher-Yates. Answer identities remain tied to original indices, so displayed order cannot change grading. All-topic quizzes balance one question per topic for 10 questions and two per topic for 20 questions. All questions must be answered before submission. Completed answers are read-only, and repeated submission cannot add duplicate history entries.

`procode.quizzes.v1` stores one active attempt and the last 20 completed attempts. Validation checks topic, bank version, existing question IDs, uniqueness, choice permutations, answers, position, and timestamps before restoring. Scores are derived from answers rather than trusting a stored score. Question and choice order are saved, so a reload does not reshuffle a session. The bank version must change when answer semantics change. Invalid quiz records are dropped with a warning; algorithm storage is unaffected. Quiz JSON export is separate from algorithm export.

No Firebase backend, accounts, paid service, or cloud database was added. This local bank is reviewable and inspectable, appropriate for personal learning. Reference links leave the app only on user activation. Completing a quiz records practice history, not an externally trusted credential.

## Later phases

Keep the `Runner` interface and replace its implementation with a backend submission API for hosted use. Move private tests and score authority to that backend. Add Firebase Auth/Firestore when cloud sync is wanted. Before that integration, limit CORS to public runtime assets and review authentication origins. Extend existing Angular/HTML/CSS adapters and add real Firebase/Git execution adapters rather than teaching a single string-matching grader every language.


## HTML and CSS practice

The deferred `WebPractice` component owns a separate editor, topic/difficulty selectors, requirements, live preview, and results. `core/web/model.ts` is lightweight metadata shared with global progress. `catalog.ts` holds 12 authored exercises and trusted requirement predicates; it loads with the component. CodeMirror HTML/CSS language extensions load on demand and share the existing theme tokens and editor assistance. Escape selects the visible Run control when multiple practice components remain mounted.

`preview.ts` parses learner HTML in an inert template, removes active/embedded content, event handlers, navigation metadata, and nonlocal asset URLs, and constructs an independent `srcdoc` document. Its iframe uses `sandbox="allow-same-origin"` without `allow-scripts`, forms, popups, or top-navigation permissions. The parent can inspect DOM and computed styles, while learner JavaScript cannot run. A restrictive CSP independently blocks scripts, remote styles/images/fonts/connections, form actions, and base URLs. CSS is escaped against closing its style element. Internal links are handled locally without navigating the frame. This is a different boundary from the algorithm executor, which needs an opaque origin because learner JavaScript is executed there. Never add `allow-scripts` to web-practice frames.

Typing refreshes the visible preview after a 250ms debounce. Run/Finish create disposable offscreen frames at actual 960px and 360px viewport widths, independent of the user's window. Predicates inspect semantics, constraints, computed styles, focus state, visibility, geometry, and overflow. Run evaluates three primary requirements; Finish evaluates all six or seven. Missing elements fail a check with its authored hint. Frames have a load deadline, are removed in finally blocks, and support cancellation on component destruction. Results replace the previous attempt without switching tabs. Preview styling is isolated from all workspace palettes.

`WebWorkspace` validates `procode.web-practice.v1`: current versioned drafts, known topic/difficulty selection, selected IDs, dates, and unique completions. It retains empty drafts and drops unknown or oversized records. Storage failures leave an exportable in-memory session. Algorithm/quiz records are untouched. Global progress includes the 18 web exercises alongside the other practice areas; web export remains a separate JSON file. These are finite learning checks, not comprehensive syntax validation or accessibility certification.

## Angular coding practice

The deferred `AngularPractice` component loads 21 exercises through `core/angular/catalog.ts`, `interview-catalog.ts`, and `crud-catalog.ts`, with shared scenario helpers in `authoring.ts`. Lightweight metadata drives navigation and progress. TypeScript uses CodeMirror's JavaScript parser with TypeScript enabled. Python, HTML, and CSS syntax support load on demand. `AngularWorkspace` validates independent versioned drafts, selections, dates, and deduplicated completions in `procode.angular-practice.v1`; empty drafts survive reload and unavailable storage leaves an exportable session. Global progress totals 92 algorithm/data-structure language challenges, 30 Clean code language challenges, 18 HTML/CSS exercises, 21 Angular exercises, 9 Firebase command exercises, 9 full-stack projects, and 9 Git workflows (188 total).

`scripts/prepare-angular.mjs` bundles the installed Angular compiler/core/common/forms/platform-browser, RxJS, and RxJS interop with esbuild, copies TypeScript and its worker, and records the installed Angular version. Generated assets live under `public/runtime/angular/` and are ignored by source control. Installation/start/build prepare them without a runtime CDN. The Angular runtime and TypeScript compiler load only when practice is run, not as initial app bundles.

The compiler worker uses TypeScript `transpileModule` with CommonJS, legacy decorators, and ES2022, returning syntax diagnostics with original positions. It adds execution checkpoints to ordinary function and loop bodies before emitting JavaScript. This does not run full TypeScript semantic analysis or AOT template checking. Runtime stack positions refer to emitted component code and are not a complete IDE source map.

Each attempt first grades inside an offscreen iframe, then bootstraps a separate interactive preview directly in its final host. Moving a live iframe would reload it, so previews are never reparented. Each scenario destroys the prior Angular application, reevaluates the module, bootstraps a standalone `AppComponent` with zoneless change detection, and exercises rendered controls through input/change/blur/click events. Assertions compare visible text, collections, values, counts, and disabled states. No learner source string is compared with a reference solution. Run selects the first three scenarios; Finish evaluates all six to twenty. `PracticeSearchApi` supplies deterministic delayed Observable results/errors to test cancellation and recovery without network access.

The iframe has `sandbox="allow-scripts allow-forms"`, **without allow-same-origin**. Forms permission permits native submit events for Angular forms; capture handlers prevent navigation and CSP `form-action 'none'` blocks outbound submissions. CSP blocks network connections, external assets, base URLs, and embedded frames. Locally bundled classic scripts plus inline/evaluated compiler output are explicitly allowed. Opaque origin prevents parent DOM/storage access. Module imports are limited to Angular core/common/forms/rxjs-interop, RxJS/operators, and the practice service. Messages require the expected frame source and random channel. Frames are removed on cancellation, section exit, or replacement; successful reruns replace prior output without switching tabs. Console/error messages are bounded and rendered as text.

Compilation has a 12-second timeout in a disposable worker. The iframe session has a 20-second completion deadline, and inserted checkpoints limit ordinary synchronous learner work to approximately one second per event-loop turn. DOM rendering requires a browser document, so Angular execution does not inherit the algorithm worker's hard termination behavior. Dynamic evaluation, pathological native calls, excessive memory allocation, or intentionally evaded checkpoints can still stall the browser. Scenarios and learner code run in the same inspectable frame; determined code can spoof outcomes. This is local personal practice, not an adversarial sandbox or trusted assessment service. Full project files, arbitrary packages, HTTP backends, AOT, and full type checking remain outside this implementation.

Primary references: [Angular Component API](https://angular.dev/api/core/Component), [bootstrapApplication](https://angular.dev/api/platform-browser/bootstrapApplication), [signals](https://angular.dev/guide/signals), and [reactive forms](https://angular.dev/guide/forms/reactive-forms).


### Local contact CRUD service

`scripts/angular-runtime/contacts-api.mjs` supplies `PracticeContactsApi` through the existing `@procode/practice` module. Each bootstrapped Angular application receives a fresh root-scoped service and seeded records. Cold Observables delay work 160ms and cancel it on unsubscribe. `list/create/update/delete` return cloned results; validation and optional version checks run before mutations. Stable IDs increase without reuse. Each accepted update increments the version. One-shot matching-operation failures produce code 503; invalid data uses 400, missing records 404, and stale versions 409. `changeElsewhere` simulates an external versioned edit.

Records persist inside that service instance across list reloads, so grading detects view-only mutations. They are never stored in ProCode's localStorage or sent over HTTP. A separate service instance for every scenario and preview prevents test contamination. The sandbox permissions and import whitelist are otherwise unchanged. Senior scenarios exercise stale updates, conflict resolution after reload, immediate optimistic removal, and exact row-order restoration on rejected deletion. The test API is deliberately inspectable personal-practice infrastructure, not a real server or trust boundary.


## Firebase command workflows

The deferred `FirebasePractice` component loads `core/firebase/catalog.ts` and the pure interpreter in `runner.ts`. Lightweight metadata in `model.ts` drives navigation/progress without loading the catalog up front. `FirebaseWorkspace` validates known versioned keys, dates, selections and deduplicated completions in `procode.firebase-practice.v1`; storage failures retain exportable in-memory work. Existing practice stores remain separate.

Each attempt deep-clones its initial virtual environment. A bounded tokenizer handles quotes, comments and supported flag forms. Command dispatch validates flags, arguments, project identities, authentication and configuration prerequisites before atomically committing one command's state. Execution stops at the first error. Limits are 50 commands and 50,000 source characters. No eval, shell process, user script evaluation, Firebase SDK, filesystem or network API is used. The quoted rules-test script is a literal fixture token, never executed.

Checks inspect final state plus deployment/preview/test history. All attempts also require zero command errors. Run and Finish check the same requirements; only Finish awards credit. Console is default, selected tabs remain stable, and edits clear stale results. A plain textarea supplies accessible command editing with Cmd/Ctrl+Enter. All output is Angular text interpolation.

This intentionally supports a teaching subset of Firebase CLI syntax. Initialization prompt answers, project aliases, Hosting sites, configuration files and emulator data are fixtures. Starting an emulator records virtual running state and returns immediately; exec records a simulated successful fixture-script result and stopped state. Export-on-exit records intent, not real persisted emulator data. No SDK CRUD, rule compilation, authorization tests, external CI, real emulators or cloud operations are provided.


## Full-stack project practice

`core/fullstack/` separates lightweight metadata, the nine-project catalog, four-file state and browser execution. `FullstackPractice` is deferred until opened; it reuses CodeMirror and existing theme tokens. `FullstackWorkspace` accepts only complete known file sets, bounds each file at 50,000 characters, preserves empty files, and validates versioned selections/completions independently of other sections. Global progress includes nine projects and totals 188 challenges. Legacy app.js drafts normalize to app.ts without source rewrites; existing versioned completion keys stay valid because the exercise goals are unchanged.

The existing compiler worker accepts a limited file-name option (`component.ts`, `app.ts`, legacy `app.js`, or `api.js`) and instruments ordinary loops/functions before emitting CommonJS. The trusted `scripts/fullstack-runtime/runtime.js` is bundled with the installed Angular compiler/core/common/forms, RxJS and platform-browser into a generated local asset during install/start/build. It loads only when a full-stack project runs. The app compiles both script files, then runs each scenario in a fresh opaque iframe at its declared width. The final interactive preview is a separate fresh iframe, so grading mutations never appear in it.

The iframe inserts CSS with textContent and evaluates the client module through an allowlisted CommonJS resolver. AppComponent is bootstrapped with real Angular; `projectTemplate` supplies index.html, and PracticeApi is provided through dependency injection. Legacy mount(api) functions still receive sanitized plain HTML. Angular template errors and the custom ErrorHandler feed Console diagnostics. The API resolver exposes only the self-contained createRouter helper, serialized into the worker. Routing parses method/path/query/parameters and supplies unmatched-route 404s; domain validation and data operations remain learner code. Its dedicated Blob worker evaluates the API module and owns the cloned initial `db`. The client gets only `api.request`; it cannot access the worker's database object directly. Requests and responses cross structured-clone boundaries, with JSON-compatible API responses. The worker serializes requests. Request timeout terminates the worker and rejects pending work; iframe removal ends the preview/session. PostMessage responses are checked against frame identity and a random per-session channel.

The iframe omits allow-same-origin, forbids network connections through CSP, allows only the local runtime script and Blob workers, and blocks form/link navigation. No real fetch transport, server filesystem, credentials, package installation, or Firebase backend exists. API errors are forwarded to Console even when the client catches the rejected request. Client execution guards are cooperative and not a hard resource boundary; finite local checks are not tamper-proof assessment.

Scenario steps interact with visible hooks, call the API directly, inject a one-shot pre-request or post-commit response failure, and assert DOM, response and worker-data state. API record collections must retain unique positive integer IDs. Responsive scenarios check a heading, labels, visible control dimensions and viewport fit at 360px. Run selects three scenarios; Finish selects all. Only a fully passing Finish records completion. Draft edits clear stale results; reruns preserve the output selection and existing preview until replacement succeeds. Navigation away aborts the attempt and disposes previews. Source and earned credit persist; practice business data does not.

## Git workflow practice

`core/git/model.ts` provides lightweight metadata, versioned keys and typed virtual repository state. `catalog.ts` contains nine fixtures and behavioral predicates; it loads with the deferred `GitPractice` component. `runner.ts` tokenizes a strictly bounded command subset and evaluates it as data. It never invokes shell processes, the Git binary, user scripts or hosted provider APIs.

Each attempt clones its fixture. Each command operates on another clone, committed only after successful interpretation. The first failed command stops execution and includes its source line in Console. Repository state models a commit DAG and snapshots, local branches/HEAD, working tree, index, origin refs, remote-tracking refs, upstreams, stash, reflog, pending merge, push history and one simulated PR. Fetch updates tracking refs independently of local branches; push checks ancestry and optional lease expectations. Main protection is an explicit fixture policy. State/history predicates grade outcomes rather than matching command strings. A command error always prevents completion even if preceding state met all exercise checks.

The interpreter has 80-command and 50,000-character bounds. Supported flags are validated explicitly; shell operators/substitution, reserved names and parent paths are rejected. Merge conflict handling compares whole-file snapshots, not Git's line-based merge engine. Conflicting rebase/cherry-pick/stash continuations are outside the subset. PR preparation validates published branches, a nonempty title and source commits absent from the target; it does not model hosted review checks or authorization. `practice write` is explicitly identified as a ProCode helper.

`GitWorkspace` separately validates versioned command drafts, provider review fields, difficulty selections and completion timestamps under `procode.git-practice.v1`. Empty drafts survive reload; unavailable storage leaves the session exportable. Root navigation and combined progress include the nine labs without changing prior exercise identities. All nine navigation controls use two rows on narrow phones; the obsolete roadmap dialog was removed because every practice section now has working content.
