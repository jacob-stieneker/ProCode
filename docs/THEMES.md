# Theme construction and provenance

The presets are ProCode adaptations of specific source colors, not exact replicas of entire applications. Source surfaces, syntax, accents, and control colors are mapped to ProCode's existing layout. Fonts and layouts remain local to ProCode; corner radii are approximate ProCode treatments, not imported vendor geometry. No theme service or runtime download is required.

## Modes and accessibility

Light and Dark use their corresponding source palettes. Each preset also contains a **complete, independent Midnight OLED palette** in `src/theme-palettes.json`. There is no fallback to Dark and no four-color overlay. The generator rejects incomplete mode definitions.

Midnight OLED uses black canvas, sidebar, and editor backgrounds, near-black panels, and low-luminance raised surfaces, controls, hover states, selection, active-line highlights, and status backgrounds. Primary actions are dark fills with readable labels, including Codex and Claude, rather than bright white buttons. Borders and off-white text separate content without large illuminated areas. Syntax is slightly tempered for black backgrounds while preserving each preset's hue family. These are authored OLED-oriented ProCode palettes, not vendor OLED exports; no hardware power measurement is claimed.

Some source colors do not meet contrast requirements on every ProCode surface. The offline generator changes luminance only as needed, preserving the source hue where possible. Text targets 4.5:1, key control borders target 3:1, and syntax is checked against editor, active-line, and selection backgrounds. Button labels choose a readable foreground. Every change is recorded with the original/applied values and tested surfaces in [theme-contrast-adjustments.json](theme-contrast-adjustments.json). Browser accessibility checks cover the actual rendered interface.

CodeMirror's syntax grammar differs from TextMate and vendor semantic engines. ProCode maps keywords, control flow, functions (including declarations), variables, definitions, properties, types, booleans, numbers, strings, comments, and punctuation separately. It does not promise token-for-token parity for every language construct.

## Maintenance

Edit the complete Light, Dark, and Midnight OLED definitions in `src/theme-palettes.json`, then run `npm run themes`. Do not edit generated `src/themes.css`. Both `npm start` and `npm run build` regenerate the CSS and adjustment report without network access. To update an upstream palette, inspect the new version, update the mappings and source manifest, regenerate, and run the appearance browser tests. The JSON is a checked-in snapshot, not an automatically synchronized feed.

Theme swatches receive their own full token set, including syntax and accent colors, rather than inheriting colors from the currently selected preset. Appearance preferences remain compatible with existing saved settings.

## Logo

The logo is a custom branching graph shaped into an open P. It replaces the P in the visible ProCode wordmark and stands alone in the favicon and compact navigation. The full accessible name remains ProCode.

## Updating the installed PyCharm snapshot

Run `python3 scripts/import-pycharm-theme.py` (or pass an alternative `/path/to/PyCharm.app`), then `npm run themes`. The importer reads the app read-only, resolves named UI colors and editor-scheme inheritance, updates only the PyCharm palette and source-manifest entries, and produces [the explicit token mapping](pycharm-token-map.json). Normal builds use the checked-in palette and do not require PyCharm to be installed. Update the picker’s version label after importing a newer release.

No PyCharm application code, fonts, icons, or complete theme archives are copied into ProCode. Light and Dark source values remain visible in the palette snapshot; accessibility changes are recorded separately in the contrast report. The full Midnight OLED definition adjusts surfaces, syntax, selection, controls, borders, and status colors, rather than replacing only the canvas.
