Command reference

Local model only. Each Run or Finish starts from the initial repository shown in State. No real files, Git repositories, accounts, or network requests are used. The fixture repository is already cloned, identity is configured, and main is protected. 

git status [--short]
git diff [--staged]
git log [--oneline] [--graph] [--all] [REVISION]
git show REVISION[:FILE]
git reflog
git branch [NAME [START]]
git switch [-c NAME] [START_OR_BRANCH]
git checkout [-b NAME] [START_OR_BRANCH]
git add FILE... | git add .
git restore [--staged] FILE...
git commit -m "MESSAGE" [--amend] [-a]
git stash push [-m "MESSAGE"] [-u]
git stash list | git stash pop | git stash apply
git fetch [origin]
git merge REVISION [--no-ff | --ff-only] [-m "MESSAGE"]
git merge --abort
git rebase REVISION
git cherry-pick COMMIT
git revert COMMIT
git reset [--soft | --mixed | --hard] REVISION
git push [-u] [--force-with-lease] origin BRANCH

The | symbols above separate alternatives, not executable pipelines. One command per line; quoted strings and # comments are accepted. Unknown flags, shell syntax, partial hashes and unlisted commands are unsupported. Commit IDs such as c2 are fixture IDs.

ProCode helper: practice write FILE "TEXT" edits a virtual file. This is not a Git command. After resolving merge content, git add marks the file resolved. File merges compare whole-file snapshots. Rebase and cherry-pick conflict continuation are outside this subset. Revert and automatic merges use generated messages instead of opening an editor. Branch switches to a different commit and stash restoration require a clean working tree in this subset.
